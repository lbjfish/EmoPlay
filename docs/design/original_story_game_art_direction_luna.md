# 原创互动剧情卡片游戏：Luna 艺术与 UX 方向

> 状态：视觉/UX 设计提案，不是源码实现。
>
> 目标：把陈柠 T1–T6 的可审计剧情，转译成一套原创、可收藏、可回看、可人工复核的恋爱剧情卡片游戏体验。
>
> 边界：角色主视觉、章节、卡面收藏、聊天/电话、关系反馈、CG 回看及剧情/导演模式均按本项目需求独立设计。所有角色、姓名、标识、文案、界面、图标、卡框、配乐和生成资产均须原创或取得明确授权。当前材料中的真人偶像代号、聊天原句和本地媒体只作为连续性审计证据，不应成为对外发布的真人肖像或明星资产。

## 1. 设计基准与体验承诺

游戏暂名 Luna，主题是“把一段逐渐靠近的聊天，收进六张有时间戳的记忆卡”。陈柠是虚构成年角色；她的四川乐山/杭州生活、外婆家的黄葛树、旺财和新刘海构成生活质感，但不把这些细节做成俗套的地域标签。

核心承诺有三条：

1. **先有被理解，再有浪漫反馈。** 每张卡先呈现她当时的心情、地点、动作和可见消息，再出现好感变化；系统不凭空制造未发生的亲密度。
2. **可收藏，也可追溯。** 卡面是情绪入口，展开后能看到 SceneSpec、证据、未来锁和人工审阅结果；“好看”不能覆盖“不合格”。
3. **温柔但不混淆状态。** 候选、已审阅、已接受、已拒绝、阻断和非最终媒体必须在颜色、文字、图标和读屏文本上同时区分。

当前实现已有的 Story/God、时间线、消息流、SceneSpec 证据/冲突/未来锁、能力状态、媒体预览、run/provider/decision 和人工接受/拒绝，是视觉设计的约束与可利用的审计骨架；艺术层不应把这些状态藏在装饰后面。章节位置会自动保存，书签与分支管理不属于玩家体验。

## 2. T1–T6 的叙事与卡面锚点

| 卡组 | 剧情时刻与主媒介 | 卡面画面/声音关键词 | 必须守住的连续性 | UX/审计状态 |
| --- | --- | --- | --- | --- |
| T1「只许看一眼」 | 雨后吃饭，给对方看新刘海；image | 杭州小餐桌、湿鞋/雨窗的间接线索、黄色宽松卫衣、锁骨发与左右不齐刘海、害羞笑 | 圆脸、单眼皮、笑时卧蚕、本人左眉尾小痣、本人左耳银月亮耳钉；发型从及胸长发变为锁骨发 | 视觉候选；只能使用此时刻前可见消息，未来消息显示锁定数量，不进入画面提示词 |
| T2「迟到七分钟」 | 早安语音；voice | 手机录音条、通勤地铁的轻节奏、困和着急；屏幕可见“早！！”但不自动播放 | 认识 13 天、上班进行中、P1“发小时候的照片”仍 open；普通话同一 speaker preset，逐字脚本 | 音频候选；精确脚本、同一音色和人类听感都未自动通过 |
| T3「树下的约定」 | 兑现 P1 的童年照片；image/CG | 二年级陈柠、红色背带裤、黄葛树、比她大一圈的旺财；照片边缘像从相册取出 | 童年不是成年脸缩小；旺财本人左耳缺口；P1 从 open 被兑现，不能读取后续消息 | 视觉候选；“Promise fulfilled”是证据标签，不能替代人工接受 |
| T4「三杯应援饮料」 | 应援咖啡店现场；image | 粉丝布置、杯套、拥挤店内、超兴奋；公开版将真人偶像替换为虚构活动标识 | P1 已 done；上班 done、应援行程 in progress；不呈现真实艺人照片或 Logo | 现场图/CG 候选；地点、物件、服装需逐项核对 |
| T5「唱到嗓子哑」 | 晚安语音；voice | 深夜手机、欢快余韵和疲惫；声音有“回来了”后的沙哑暗示但不伪造真人声纹 | 同一角色身份；当晚去应援咖啡再唱 K；脚本逐字；Tingting rate 180/220/320 与 Sinji 等只作候选对比 | 已有候选与拒绝假设；最终好感反馈只能在人工听审后出现 |
| T6「证明你是真的」 | 纸条自拍；image | 日常光线、手写纸“阿杰 10.16”、略迟疑后认真配合 | 认识 14 天、前天剪发、平常情绪；纸面文字逐字、左右与耳钉一致；没有未来锁 | 视觉候选；纸面 OCR/人工逐字核验优先于装饰效果 |

卡面标题可以是原创短句，但不改写为“官方剧情结论”。在卡片详情中显示 `trigger_id`、UTC/本地化时间、kind、why、当前 mood、relationship days 和审计徽章；必要时提供“查看原始证据”折叠层。

## 3. 三个艺术方向

### 方向 A（推荐）：雨后柠檬手账 · 轻电影写实

以手机相册、手账纸、雨后玻璃和餐桌暖光为共同材质；人物是半写实插画/轻电影摄影感，不追求真人脸替代。卡面像一页被保存的生活证据，边角有日期、天气和一句当时的心情，但证据文字与装饰文字明确分层。

- **情绪**：亲近、笨拙、可呼吸，适合 T1 的害羞、T3 的童年温度和 T5 的夜间余韵。
- **色彩**：米白纸张、深墨蓝文字、柠檬黄高光、雨水青、微量珊瑚红（只给好感/完成反馈）。
- **材质**：纸张颗粒、铅笔圈注、玻璃高光、低对比胶片颗粒；不使用真实聊天 App 的视觉皮肤。
- **优点**：能承载生活连续性和审阅证据，卡面收藏有辨识度，静态也成立；减少动画依赖后仍有温度。
- **代价**：需要控制纹理强度，避免小字对比度下降；写实人物仍需统一左右、年龄、发型和配饰。

### 方向 B：纸片舞台 · 明亮编辑插画

把每一章当作一组可移动的纸片：人物半身、地点小物、对话便签和承诺印章层叠组成卡面。T3 可采用相册开页，T4 可采用活动贴纸，但所有元素都使用原创几何形状和图标。

- **情绪**：轻快、可玩、收藏感强，适合大量卡面和分支。
- **优点**：形状化元素易做响应式和无障碍标记；候选/接受/锁定可以通过“纸片夹/封条/印章”表达。
- **代价**：若阴影与贴纸太多，容易像儿童产品；童年 T3 与成年 T1 的年龄区别需要靠人物比例和叙事标签，不应靠夸张脸部。

### 方向 C：夜航胶片 · 深色叙事电影

主背景是深蓝夜色与低饱和青绿，卡面像片段式电影分镜；手机录音、雨夜、K 歌后的走廊和城市灯都成为声画切片。成功反馈是“画面定格+一句克制的关系变化”，不做闪耀抽卡。

- **情绪**：克制、成熟、适合夜间阅读和声音内容。
- **优点**：T2/T5 音频、审阅状态和 CG 回看有强聚焦；大图与短句在桌面端很有表现力。
- **代价**：深色 UI 的文字对比度、低视力用户和移动户外阅读压力更高；T3 的童年暖意必须额外用暖色光源建立。

### 选择

推荐方向 A，必要时吸收方向 B 的“纸片标记”作为审计图例，吸收方向 C 的夜间播放器层。原因是它在“原创恋爱感”和“可验证的生活证据”之间最平衡：不依赖夸张偶像化，也不把候选媒体伪装成已经发生的最终剧情。方向 B 适合后续活动/收藏扩展，方向 C 只建议用于 T2/T5 的音频查看状态与深夜主题。

## 4. 推荐方向的视觉系统

### 4.1 色彩 token

色彩必须有文字标签和形状/图标冗余，不能仅靠红绿判断状态。以下是亮色基线；深色主题使用同语义的高亮 token，并先做对比测试。

| Token | 建议色值 | 用途 | 约束 |
| --- | --- | --- | --- |
| `paper` | `#FFF9EF` | 页面/卡面底 | 不用于小字文字 |
| `ink` | `#1B2430` | 正文、标题 | 亮底正文目标至少 7:1 |
| `ink-muted` | `#536273` | 时间、辅助说明 | 至少 4.5:1；不承载唯一状态 |
| `rain-blue` | `#2E6F95` | 主链接、选中、Story 主线 | 选中同时有边框/底纹 |
| `lemon` | `#E7B93E` | 陈柠识别色、主视觉小亮点 | 只作面积色/图标底，不直接放浅黄小字 |
| `coral` | `#C85755` | 好感上升、兑现、成功 | 同时显示“+好感/已兑现” |
| `mint` | `#3A806B` | 人工接受、可回看 | 必须带“Accepted”文字 |
| `amber` | `#A86616` | 候选、需审阅、未来锁提示 | 必须带“Candidate/Locked”文字 |
| `brick` | `#A73737` | 拒绝、阻断、未知计费 | 同时说明原因和下一步 |

### 4.2 排版与层级

- 中文优先使用系统无衬线：`-apple-system`, `BlinkMacSystemFont`, `PingFang SC`, `Noto Sans CJK SC`, `Microsoft YaHei`, sans-serif；标题可用一款授权的窄字重字体，但正文不依赖远程字体。
- 桌面 H1 32/40、H2 22/30、H3 16/24、正文 15/24、辅助 13/20；移动端 H1 26/34、正文至少 16/26。避免卡面塞入小于 12px 的证据字。
- 一张卡只保留一个视觉主语：人物/关键物件占 60–70%，标题和时间占 20%，状态与动作入口占 10–20%。
- 阅读顺序固定为“章节/时间 → 画面 → 角色一句话 → 媒体状态 → 审计详情”。状态徽章不能覆盖人物脸或纸条文字。
- 统一 8px 间距基线；卡片圆角 12px，操作按钮圆角 8px；阴影低于材质对比，不用发光制造层级。

### 4.3 卡片与组件语法

卡片有四种公开状态：`Candidate 候选`、`Reviewed 已审阅`、`Accepted 已接受`、`Rejected 已拒绝`，另加不可发送的 `Blocked 阻断`。每种状态都组合颜色、图标、文字和边框样式；例如候选为琥珀色虚线+“候选/需人工审阅”，接受为薄荷色实线+“人类已接受+SHA 已复核”。

卡片正面：原创场景缩略图或安全占位、T 编号/章节名、时间、媒介类型、情绪色条、收藏状态。卡片背面/详情：SceneSpec 摘要、触发原因、承诺、地点/服装/动作、证据条数、未来锁条数、媒体 hash 摘要、provider/billing 状态和“审阅”入口。对于没有实际媒体的 T1/T3/T6，不用伪造缩略图，显示“尚无可审阅媒体”。

## 5. 交互架构（保留通用语法，完全原创命名与皮肤）

| 体验层 | 玩家看到的东西 | 与当前审计功能的连接 |
| --- | --- | --- |
| 角色主视觉 | 首页陈柠当时状态的立绘/生活剪影；可点开当前章节和最近一张卡 | 只读取当前 checkpoint 的 position；身份锚点与发型状态显示为可核对标签 |
| 章节 | “雨后的新刘海”“树下的约定”等六章时间轴；当前章高亮，后续章折叠 | Story 模式只允许按触发顺序推进；后续内容显示锁定数量，不泄露文本 |
| 卡面收藏 | 按 T1–T6、image/voice、情绪和状态筛选；接受后可回看 | 对应 assets、candidate/final_media、review decision；收藏不等于 final eligible |
| 聊天 | 左右气泡、时间分组、媒体气泡；触发消息有纸夹标记 | visible/trigger/future message flow；God 模式才可打开全量证据 |
| 电话/语音 | 波形、播放/暂停、逐字脚本开关、速度不默认修改；“可发送”与“候选”分开 | T2/T5 的 exact script、same preset、人工听审、duration 和 hash |
| 好感反馈 | 只在玩家完成一次有证据的查看/回复/兑现后，出现小幅“关系靠近 +1”及依据 | 反馈必须引用触发原因或 fulfilled promise；失败/阻断不加好感，不把生成成功当关系成功 |
| CG 回看 | 以时间轴、地点和一句情绪旁白组织，不做无止境自动轮播 | 媒体预览带 role/provenance/final eligibility；缺媒体时可看设计卡但标注不可发送 |
| 剧情模式 | 沉浸式阅读，隐藏审计复杂度但保留“候选/锁定”提示 | 等同 Story：未来信息不可见、操作按当前 position 记录 |
| 上帝模式 | 评审者可看完整 evidence、conflicts、future locks、provider 和 decisions | 等同 God：只读证据优先，明显标注“含剧透/非玩家流程”；不通过 God 直接改成 final |

聊天页的视觉中心是人物状态和时间，不是仿造某一即时通讯 App。电话页的声音波形必须是实际音频的可复核元数据或安全占位，不得用漂亮波形暗示“音频已合格”。

## 6. 动效、声音、粒子与成功反馈

动效节奏采用“轻、短、可取消”：页面转场 180–240ms，卡面展开 220–320ms，状态徽章只做一次 120ms 的透明度/边框变化。避免持续漂浮、闪烁、自动翻卡和大面积粒子遮挡证据。

- **T1**：雨线/窗面高光只在背景层低速移动；打开卡面时可有一次纸张轻响。
- **T3**：翻相册的声音与树叶环境声可作为可选氛围；旺财耳缺口和红背带裤不靠粒子强调，必须靠画面与文字核验。
- **T4**：应援彩带只做静态贴纸或一次短促飘落；真实艺人图像/Logo 不进入资产包，使用原创虚构活动牌。
- **T2/T5**：声音播放以用户主动点击开始，默认静音；播放条显示时长、进度、脚本开关和当前审阅状态。
- **成功反馈**：完成“看完证据→确认动作→记录决定”后，卡片边框从琥珀变薄荷，出现“已由人类接受 · hash 已复核”与可展开理由；好感反馈另以图标+文字出现。生成结束但未审阅时只显示“候选已生成”，不放庆祝粒子。
- **阻断反馈**：未知计费、超时或未来锁冲突用静态红砖提示条，说明“停止重试/等待人工核对”的原因；不使用失败音效羞辱用户。

## 7. 移动端与桌面端布局

### 桌面（≥1080px）

采用三栏评审工作台：左侧 240–300px 章节/收藏，中间 560–760px 主卡或聊天/CG，右侧 320–420px 审计抽屉。主视觉卡可占中栏上半部，右侧审计始终可见状态摘要。God 模式允许右侧展开为证据宽栏，但保留“退出上帝模式”的显著按钮。

### 平板（741–1079px）

章节条横向滚动置顶；主内容在上，审计与媒体状态用可折叠面板置底。不要把三个完整列强行压缩为不可读的表格。

### 手机（320–740px）

顺序为：顶栏/当前章节 → 主视觉或聊天 → 媒体播放 → 好感变化 → “查看证据/审阅”按钮 → 后续卡片。章节采用可横滑的编号节点，但当前卡要在页面标题中重复 T 编号和时间，避免只凭颜色定位。审计详情用原生 disclosure/底部抽屉，所有主要按钮最小触控区域 44×44px；生成、接受、拒绝等破坏性/不可逆动作需要二次确认并展示当前 hash/理由输入。

桌面与移动共用同一语义顺序和状态文本；响应式只改变位置，不改变“候选先审阅，接受后入收藏”的流程。

## 8. 无障碍与 reduced motion

- 全流程可键盘完成：跳过链接、章节节点、卡片、播放控制、审阅表单和详情折叠均有可见焦点；焦点环至少 3px，并且不被抽屉裁切。
- 所有图片使用描述性 alt：包含场景、人物动作和可核验物件（例如“童年陈柠穿红色背带裤，在黄葛树旁抱住左耳有缺口的旺财”）；纯装饰纹理用空 alt。
- 不把“黄/绿/红”作为唯一状态。屏幕阅读器需读出“候选，需人工审阅”“已接受，human accept，hash 已复核”“阻断，计费未知”等完整词组。
- 聊天和证据正文支持放大到 200% 不丢失横向信息；长消息可复制；不要以图片承载纸条文字或关键脚本。
- 播放器提供暂停、音量、速度、文字脚本；不自动播放语音或背景声。错误信息放入 `role=alert`，连接/生成进度放入 `aria-live=polite`，不连续朗读每条粒子动画。
- `prefers-reduced-motion: reduce` 时关闭雨线、纸片飞入、波形跳动、闪光和视差；卡片直接出现，状态用静态边框/图标/文字完成。另提供“关闭氛围声”和“高对比度”开关。
- 不以真实人物照片、录音或声纹克隆建立角色；公开版只使用虚构成年角色资产和可授权的原创/系统声音。

## 9. 真实评审流程（设计必须支持，不可用动画代替）

1. **预检**：在本地 loopback 评审台选择 T1–T6，确认当前 checkpoint、SceneSpec hash、时间和 future lock 数；候选、placeholder、prompt-only、fixture 初始都不可发送。
2. **视觉连续性审阅**：逐张查看身份锚点、左右标记、年龄、发型、耳钉、衣物、地点、动作和纸面文字。T1、T3、T4、T6 分别按 scene spec 核对；T3 先核对 P1 fulfilled，不把 T1 成人发型带入童年。
3. **声音审阅**：主动播放参考音频和 T2/T5；核对 speaker identity、逐字脚本、语速、可接受听感和时长。T5 的 rate 180/220/320 与错误 locale 候选用于对比，但“after”仍是候选，不能靠文件名取代决定。
4. **逐项记录决定**：选择 Accept 或 Reject，输入具体理由；界面显示 asset path、size、SHA-256 和 provenance。Accept 重新核验 hash 后写入人类 decision 与 checkpoint；Reject 保留候选和理由，不能删除历史调用或费用。
5. **阻断处理**：provider timeout/5xx/unknown billing、缺少 accepted reference、future leak、hash 不一致、纸条/脚本不准确均 fail closed。未知计费不自动重试，也不把“生成完成”显示成“关系完成”。
6. **最终审计**：只有 `final_media` 中具有人类接受证据的 reference visual、reference voice、T1、T3、T5（以及产品决定纳入的 T4/T6）才显示“可发送”；至少三条带 human reject 和理由的候选在审计台中可追溯。release audit 仍是最终门，视觉设计不替代命令行/存储审计。

审阅者路径应能在 5 分钟内完成一轮：**选择章节 → 看主卡 → 展开证据 → 播放/放大媒体 → Accept/Reject + 理由 → 回到卡面查看状态**。如果没有实际媒体，按钮改为“记录缺口”，不伪装成空白 CG 已完成。

## 10. 媒体资产清单

### 最小可评审资产（必须带元数据）

| 类别 | 数量/用途 | 资产要求 |
| --- | --- | --- |
| 身份视觉 reference | 1–4 张，至少正面与 3/4 角 | 虚构成年陈柠；圆脸、单眼皮、左眉尾痣、左耳银月亮耳钉可见；无真人照片；记录 role=reference、尺寸、hash、生成/来源和审阅决定 |
| T1 | 1 张 image | 餐桌/雨后氛围、新刘海、黄色卫衣；不读未来消息；与 accepted reference 绑定 |
| T3 | 1 张 image/CG | 二年级、红背带裤、黄葛树、旺财比她大、旺财本人左耳缺口；兑现 P1；童年年龄比例自然 |
| T5 | 1 条 voice | 逐字脚本、同一 speaker preset、记录时长与参数；人工听审通过后才可 final |
| T2 | 1 条 voice（建议） | 早安脚本、困急语气；和参考声音同身份；candidate/final 状态分开 |
| T4 | 1 张 image（建议） | 原创虚构应援店与杯套；不使用真实偶像照片/Logo；地点和兴奋情绪可核验 |
| T6 | 1 张 image（建议） | 手持纸条“阿杰 10.16”；纸面文字优先做 OCR+人工核验；不遮挡左右耳/眉尾连续性 |

### UI/氛围资产

- 角色主视觉 1 组：首页、章节头图、卡片缩略图的同一身份裁切规则；另准备无媒体安全占位，不把占位图列为 final。
- 地点背景：雨后餐桌、通勤提示、黄葛树相册页、虚构应援咖啡店、夜间房间；背景可复用，但每张卡的时间与地点标记要来自 SceneSpec。
- 卡框/徽章：候选、锁定、接受、拒绝、阻断、P1 兑现；使用原创线形与纸夹/封条造型，不模仿现成游戏卡框。
- 交互图标：播放/暂停、脚本、证据、未来锁、hash、人工决定、收藏；全部提供 SVG/文字替代或 CSS 形状，避免仅靠 emoji。
- 声音：可选纸张/雨声/室内底噪，分轨、可关闭、无版权不明来源；成功/失败提示用短促低音或静音可选，不自动播放。
- 粒子/动效：雨滴、纸屑、相册页阴影的低频版本；为 reduced-motion 提供空实现。

### 交付元数据（每个媒体必填）

`asset_id`、`media_type`、`role`、`trigger_id`、`scene_spec_sha256`、`path`、`size_bytes`、`sha256`、`provenance`、`provider/model`（如适用）、参数摘要、duration（音频/视频）、`candidate/final_eligible`、`human_review_required`、`decided_by`、`decision`、`reason`、decision 时间。任何未知项宁可显示“未知/阻断”，不填一个看似完整的默认值。

## 11. 完成判定

这套视觉方向只有在以下条件同时满足时才算“可审阅”，而不是“看起来完成”：

- 六个章节都有可识别的时间、媒介和连续性标签；T1–T6 的 SceneSpec 未来锁不被剧情模式泄露。
- 卡面、聊天、电话、CG、Story/God 都能回到对应 evidence，并区分 candidate 与 final。
- 好感反馈只由有证据的剧情动作触发；候选生成、provider 成功、动画结束都不自动增加好感。
- 人工接受/拒绝可记录具体理由并与 asset hash 绑定；三条拒绝记录可在上帝模式复核。
- 移动端、桌面端、键盘、读屏、高对比和 reduced motion 路径保留同一状态语义。
- 未生成或被阻断的媒体以缺口/阻断展示，不用占位图、文件名或装饰性成功动画冒充最终成果。
